# Entity Prioritization Roadmap

Документ фиксирует порядок, в котором расширяем список сущностей для синтетического генератора и будущей модели PII Detection.

Главная идея: не пытаться сразу тащить все 100+ сущностей. Сначала берем ядро, которое дает максимум пользы для обычного PII Detection и для PsyTechLab, а редкие и сильно доменные сущности оставляем на следующие итерации.

## Зачем это нужно

* В таблице сейчас около 100 сущностей, но не все одинаково важны.
* Для PsyTechLab полезно широкое покрытие: контакты, аккаунты, документы, чувствительные атрибуты, редкие способы связи.
* Для бизнесового PII Detection важнее другое: сущности, которые чаще всего надо маскировать в пользовательских данных.
* Поэтому первый этап — не “добавить всё”, а собрать сильное ядро примерно из 30 сущностей.
* Такой подход уменьшает шум, откладывает часть regex-коллизий и быстрее дает рабочую модель.

## Критерии приоритета

Сущность выше в списке, если она:

* часто встречается в real dataset;
* является прямым идентификатором человека;
* является контактом или аккаунтом для связи;
* является документом или финансовым идентификатором;
* важна для маскирования PII в бизнесовых данных;
* нормально генерируется синтетически;
* не слишком сильно дублирует уже добавленные сущности;
* не требует прямо сейчас решать много сложных regex-коллизий.

## Stage 1: ядро до 30 сущностей

Это первый target set. Его задача — быстро расширить систему до нормального ядра для baseline-модели.

* `Адрес` — уже есть пул; самый частый тип в real dataset; нужен почти всегда.
* `ФИО` — уже есть пул; базовая PII-сущность.
* `Телефон` — уже есть пул; прямой контакт.
* `Email` — уже есть пул; прямой контакт и классический PII.
* `Telegram` — уже есть пул; очень частый контакт в пользовательских текстах.
* `VK` — уже есть пул; важный российский social/contact identifier.
* `Никнейм` — новый пул; частый online identifier, особенно в форумах и чатах.
* `Возраст` — новый пул; частый биографический атрибут в real dataset.
* `Пол` — новый пул; частый биографический атрибут, полезен для PsyTechLab и privacy.
* `Рост` — есть в real dataset, но ниже бизнес-приоритет, чем документы и контакты.
* `Вес` — аналогично росту; полезно для PsyTechLab и privacy.
*  `ORGANIZATION` частично покрывает это, но должности и место работы лучше явно доработать.
* `Паспорт РФ` — уже есть пул; ключевой документ для PII Detection.
* `СНИЛС` — новый пул; классический российский персональный идентификатор.
* `ИНН Физическое лицо` — новый пул; персональный налоговый идентификатор.
* `Полис ОМС` — новый пул; медицинский документ и чувствительная PII.
* `Водительское удостоверение` — новый пул; распространенный документ.
* `Дата рождения` — спорный новый пул; можно временно объединить с `Возраст`, но точная дата рождения сильнее идентифицирует человека.
* `Банковская карта` — уже есть пул; финансовая PII с высокой бизнес-важностью.
* `Банковский счет` — новый пул; важный финансовый идентификатор.
* `IP-адрес` — новый пул; классический цифровой идентификатор.
* `WhatsApp` — новый пул; контактный канал, близкий к телефону и мессенджерам.
* `Discord` — новый пул; есть в real dataset и часто встречается как online contact.
* `Github` — новый пул; важен для developer/career текстов.
* `Instagram` — новый пул; популярная соцсеть.
* `hh.ru (HeadHunter)` — новый пул; важен для career/person data.
* `LinkedIn` — новый пул; бизнесовая career/social платформа.

## Спорные решения

* `Возраст` и `Дата рождения` можно объединить на первой итерации, если хочется меньше labels. Но для строгого PII masking дата рождения обычно важнее возраста, поэтому ее полезно держать отдельно.
* `Организация`, `Место работы / Должность` и `Профессия` пересекаются. Для первой модели можно оставить `ORGANIZATION`, а потом разделить работу, должность и профессию аккуратнее.
* `AUTHOR_LINKS` и `OTHER_CAREER_PLATFORM` есть в real dataset как удобные разметочные обобщения, но в таблице лучше раскладывать их на конкретные сущности.
* Игровые аккаунты полезны для PsyTechLab, но для бизнесового PII Detection они ниже приоритета, чем документы, контакты, финансы и адреса.

## Практический порядок работы

* Взять Stage 1 как первый target set.
* Для новых сущностей собрать или сгенерировать пулы.
* Вручную просмотреть пулы и убрать очевидный мусор.
* Сгенерировать синтетический датасет на расширенном наборе.
* Обучить baseline на `BERT` или `GLiNER`.
* Проверить качество на real dataset из Label Studio.
* По ошибкам решить, какие Stage 2 и Stage 3 сущности добавлять следующими.
